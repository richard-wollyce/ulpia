This is the catalogue's own card index. The four pages before it tell the story; this one lists the verbs, their flags, the fields a program reads, the codes the linter prints and the files on disk, each copied from the source at commit ea43d1d on 2 September 2026 rather than remembered. Where a line had to be assembled instead of copied, the entry says so. Nobody is expected to read it through.

The sixteen verbs

The usage block

What kb --help prints, minus its prose. The block carries sixteen lines for fifteen verbs, init twice; answer has no line in it and is assembled below. 

kb check [path]... [--strict] [--all]
kb index [path]... [--json] [--all]
kb route <question> [path]... [--top N] [--hybrid] [--json] [--all]
kb remember <claim> [path]... [--all] [--json]
kb init <name> [fleet-root]
kb init --person [fleet-root]
kb write <agent> <slug> [fleet-root] --keys <a, b> --summary <one line> [--folder F]
kb fleet [path]... [--all]
kb blocks [path] [--emit]
kb eval <gold.tsv> [path]... [--top N] [--all] [--classify]
kb commit <path>... -m <message>
kb boot [path]... [--top N] [--all]
kb promote [path]... [--top N] [--all] [--dry-run] [--max N] [--lock]
kb ui [path]... [--port N] [--all]
kb capture [path] [--session ID]
kb serve [path]... [--top N] [--all]

Verb by verb

Each entry is the usage line, what the verb does, and the one thing it never does. The last sentence is the one to hold it to.

kb route <question> [path]... [--top N] [--hybrid] [--json] [--all]
Asks the catalogue which books a question should open. The question is scored against every note's Search for line, the owner agent is named, and the verdict is one of hit, guess or nothing. --hybrid fuses the keyword ranking with full text search over the chunks; --json prints the whole answer as one line on stdout and always fuses, so --hybrid adds nothing on top of it. It never calls a model and never invents a file.
kb answer "<question>" [path]... [--expanded | --complete]
Assembled, not copied: --help carries no usage line for this verb, so the line above is put together from the README's example and from the dispatch in the source, which also reads --top N and --all. It runs route, then hands only the served passages to the command named by answerer = in fleet.txt, which must ground every claim in them or say plainly that they do not hold the answer. The default reads the top five files in one model call; --expanded reads up to twelve; --complete reads the whole base in batches of ten and prints its estimate before the first call. It never reaches the model on a nothing verdict, and without an answerer line it prints the reading list route would have printed, except in --complete, which is nothing but model calls and stops instead.
kb remember <claim> [path]... [--all] [--json]
Measures a claim against what the library already holds and proposes ADD, UPDATE or NOOP, with the overlapping passage as evidence. The measure is containment, the fraction of the claim's words already present in one chunk: NOOP at 0.90 or above, UPDATE at 0.55 or above, ADD below. It writes nothing, and it never proposes DELETE, because absence and falsehood look the same to a word count.
kb write <agent> <slug> [fleet-root] --keys <a, b> --summary <one line> [--folder F]
Reads the note body on stdin and writes the keys twice: into the note's own Search for header, which is the only thing the catalogue indexes, and into an entry in the agent's MAP.md, which is a reading list for a person. --folder defaults to knowledge, --provenance to agent and --stage to derived. It refuses without keys, and there is no flag to skip them; it also refuses when the agent has no MAP.md. It never leaves half a write behind: a failed map entry deletes the note again.
kb promote [path]... [--top N] [--all] [--dry-run] [--max N] [--lock]
Reads each agent's inbox/ and offers what it finds to two promoters. The first proposes notes and never sees the base; the second decides, three times through three different questions, and never sees the first one's reasoning. Only a unanimous accept writes, at stage captured, and a refusal is counted in kb-rejections.txt. --dry-run decides everything and writes nothing; --max N stops after N proposals are admitted and leaves the rest of the deposit where it is; --lock refuses to start while another run holds .kb-promote.lock. It never writes on a split decision.
kb check [path]... [--strict] [--all]
Lints every base and reports what the conventions promise while nothing was checking. The exit code is 1 when it finds errors, or when --strict is given and it finds warnings. It fixes nothing and touches no file. The codes are listed below.
kb index [path]... [--json] [--all]
Builds one SQLite file per base at <base>/.kb/index.db from the markdown, content hashed so that an unchanged file costs nothing on the next run. --json prints the index entries as JSON instead of building the index. It never runs in the background, and it holds nothing that cannot be rebuilt from the files.
kb eval <gold.tsv> [path]... [--top N] [--all] [--classify]
Grades the catalogue against a gold file of questions and expected answers, including the questions it is supposed to refuse. --classify asks the command that chooses the agent, named by classifier = in fleet.txt, about every question, one model call each. It refuses to grade a gold file that names files the fleet does not have, because grading against a stale gold file reports a wrong number confidently.
kb boot [path]... [--top N] [--all]
The librarian at the door. On a UserPromptSubmit hook it reads the message from stdin, routes it across the fleet, and prints the owner's constitution to stdout, where the runtime injects it; the constitution is emitted only when the routed agent changes, tracked per session under .kb/sessions/. Below the gate it picks nobody and emits the roster instead. It always exits 0, because exit 2 on that event erases the user's message and exit 1 shows them a hook error.
kb blocks [path] [--emit]
Reads blocks.txt and reports each block's mode, files, bytes and tokens, then what changing each one costs in tokens that have to be prefilled again. --emit prints the assembled resident constitution instead of the report. It never invents a block that is not on disk.
kb fleet [path]... [--all]
Prints the fleet's name and roster, read from fleet.txt and from each agent.txt; it is the same text kb_fleet returns over MCP, so what a model sees and what a person sees cannot drift apart. Identity is never derived from the index.
kb init <name> [fleet-root]
kb init --person [fleet-root]
Generates a base in the shape the catalogue needs, under <fleet-root>/fleet/<name>, served as it stands: no repository is needed and none is created. --person writes the person's base, which has no agent.txt, so the catalogue reads it and can never choose it as the one who answers. It never writes a word about the person; the skeleton is empty on purpose.
kb commit <path>... -m <message>
Commits exactly the paths named, through git commit -- <paths>, then reads the commit back and prints what it left dirty. There is deliberately no flag meaning everything. It refuses an empty path list, a blank message, and a list that spans two repositories.
kb serve [path]... [--top N] [--all]
Speaks the Model Context Protocol over stdio, with four tools, kb_route, kb_retrieve, kb_remember and kb_fleet, all through the same Memory contract the command line uses. It writes nothing to stdout that is not protocol; every diagnostic goes to stderr. It never serves the private layer unless --all says so.
kb ui [path]... [--port N] [--all]
The reading room: a local page over the same contract. It binds 127.0.0.1 and nothing else, on port 4114 unless --port says otherwise, and there is no flag for any other address. It never serves a file discovery did not produce, however the path is spelled.
kb capture [path] [--session ID]
Turns a session's record into a deposit: one markdown file in the last routed agent's inbox/, raw and without a Search for line, so the catalogue never names it and every passage from it is labelled short memory. The session id comes from --session or from the hook payload on stdin, the same JSON boot reads. It runs no model, writes no Search for line, and captures nothing from a session no agent was routed in.

Shared flags

path
The base to work on. Defaults to the current directory. A path may also be a fleet root, a directory that is not itself a base but whose immediate children are; both are accepted and neither is required.
--top N
How many candidates to carry. Default 5. route, boot, eval, promote and serve all read it.
--all
Include the private layer, and nothing else: the folders a base declares with a private = line in agent.txt, or profile/, projects/ and records/ when it declares nothing. . declares the whole base, and the person's base is whole by name. Nothing outside the base is consulted, and no repository is needed.

kb route --json, field by field

One line of JSON on stdout, computed in one pass: the owner and the verdict from the keyword ranking, the reading list from the fusion of both scorers. Every score in it is rounded to six decimals, because the keyword score is a 32-bit float and widening it would print seventeen digits of precision it never had. When the base cannot be opened, stdout carries {"question": ..., "error": ...} and the exit code is 1.

The shape

Types rather than values, so nothing here is an example that could go stale. A vertical bar separates the values a field can take. 

{
  "question": string,
  "verdict": "hit" | "guess" | "nothing",
  "gate": {
    "served": bool,
    "ranked_by_text_only": bool,
    "floor": number
  },
  "confidence": {
    "agreement": 0 | 1 | 2,
    "keyword_score": number,
    "margin": number
  },
  "agent": null | {
    "name": string,
    "score": number,
    "files": integer,
    "margin": number | null,
    "contenders": integer,
    "totals": [ { "agent": string, "score": number } ]
  },
  "keyword_top": string | null,
  "indexed": {
    "entries": integer,
    "agents": integer,
    "aliases": integer
  },
  "skipped": [ string ],
  "index_was_rebuilt": bool,
  "suggestions": [ string ],
  "miss": null | {
    "question": string,
    "looked_like": [ string ],
    "date": string,
    "log": string,
    "recorded": bool,
    "error": string | null
  },
  "results": [ {
    "base": string,
    "path": string,
    "memory": "short" | "long",
    "title": string,
    "purpose": string,
    "score": number,
    "keyword_score": number,
    "why": [ string ],
    "matched": [ string ],
    "passages": [ {
      "heading_path": string,
      "text": string,
      "excerpt": string,
      "provenance": string | null,
      "stage": string | null
    } ]
  } ]
}

The top level

question
The question, as it was given.
verdict
hit, guess or nothing: the top file's keyword score against the floor for this fleet's size, and never hit in a base with fewer than two entries. The margin over the runner-up is reported under confidence and does not gate. It answers whether the keyword scorer ranked anything worth serving; it does not answer whether either scorer ranked anything at all, which is what gate is for.
keyword_top
The file the keyword scorer ranked first, as base/path, or null when it ranked nothing.
indexed.entries
indexed.agents
indexed.aliases
How many keyed entries, agents and alias lines were opened for this answer. An entry is a note with a Search for line.
skipped
Bases the open had to leave out, named here rather than only on stderr, because a caller that reads stdout alone must not read an empty result set as a base that does not cover the question. Empty since the day git left the runtime: the one reason a base used to be left out no longer exists, and the field stays because callers read it.
index_was_rebuilt
true when an index built before the private column existed was found and emptied on open. Run kb index before relying on the passages.
suggestions
The vocabulary the base does know that looks like the words used, by character trigram overlap; the same list miss.looked_like carries. Empty when the answer was served, and empty on a miss with no orthographic neighbour, which is an honest answer.

gate and confidence

Branch on gate.served, never on the length of results. A refused answer still carries its candidates, because the verdict comes from the keyword scorer and the results come from both, so "verdict": "nothing" with a full array is an ordinary outcome rather than a contradiction.

gate.served
Whether the answer is served: false exactly when the verdict is nothing. The rule stated as a field, so a caller does not have to re-derive it from a string.
gate.ranked_by_text_only
true when the answer was refused and results is not empty: the text scorer ranked files the keyword lines missed, which is a base whose labels need a word rather than a base without the subject. false with an empty results means nothing ranked anywhere.
gate.floor
What confidence.keyword_score was measured against, for this fleet's size, never the calibration constant. A caller who disagrees with the gate needs the threshold that actually applied.
confidence.agreement
How many of the two independent scorers ranked the top file: 0, 1 or 2. Reported and never used to gate.
confidence.keyword_score
The top file's raw keyword score. Zero when only the text scorer found it.
confidence.margin
The top keyword score divided by the best runner-up's, and 1.0 when nothing else scored, because standing alone is not the same as winning.

agent

null when no agent scored. Otherwise the owner the fold chose, with the numbers a caller holding an incumbent would need to argue with it.

agent.name
The owner agent.
agent.score
The agent's total in the fold.
agent.files
Since ADR-0031 this counts species with evidence, memory, skills or tools, at most three per agent, and no longer files: fifty-nine matching files and one matching file are the same one species.
agent.margin
Over the runner-up agent. null when only one agent scored at all, which is JSON's encoding of infinity and means maximum confidence rather than a missing field: no other base in the fleet had anything to say.
agent.contenders
How many agents scored anything.
agent.totals
Every agent that scored, best first, each as {"agent": ..., "score": ...}.

miss

null when the answer was served. On a refusal it is the recall loss itself, handed back rather than only logged, and it repeats question and the suggestions on purpose: the object exists to be copied whole into somebody else's store by a caller that has nowhere of its own to write.

miss.question
The question, again.
miss.looked_like
The vocabulary offered back, the same list as suggestions.
miss.date
The day it was seen, in the log's own format.
miss.log
Where the log was written, or where the attempt was made.
miss.recorded
Whether the log holds this too. false means the caller holds the only copy.
miss.error
Why the write failed, when it did, and null otherwise. A failed write does not fail the query.

results and passages

One entry per ranked file, best first. Two scores travel because they answer different questions: fusion says which file to read first, and the keyword score is the number the verdict was measured against.

results[].base
results[].path
The agent and the path inside it.
results[].memory
short or long. Short is the deposit, inbox/: recent, unjudged, served on purpose and labelled on purpose. A caller that wants only settled knowledge filters on long.
results[].title
results[].purpose
The note's title and its Exists to line.
results[].score
The fused score.
results[].keyword_score
The raw keyword sum for this file.
results[].why
Which scorer ranked it and where, one string per scorer.
results[].matched
The query words that matched, so a bad ranking can be diagnosed instead of guessed at.
results[].passages[].heading_path
Where in the note the chunk sits, as Title > Section > Subsection.
results[].passages[].text
results[].passages[].excerpt
The chunk, and a shorter cut of it.
results[].passages[].provenance
results[].passages[].stage
From the note's front matter, or null when the note declares neither.

kb remember --json

The proposal as one line, for a caller that is not a person. It measures overlap, proposes, writes nothing and needs no model, which is what lets an agent with no writable filesystem ask whether a fact is worth keeping, queue the answer, and apply it later on a machine that has the files. 

{
  "claim": string,
  "proposal": "ADD" | "UPDATE" | "NOOP",
  "reason": string,
  "evidence": [ {
    "base": string,
    "path": string,
    "heading_path": string,
    "excerpt": string,
    "containment": number,
    "shared": [ string ],
    "missing": [ string ]
  } ],
  "notice": string
}
claim
The claim, as it was given.
proposal
ADD, UPDATE or NOOP. There is no fourth value.
reason
One sentence saying what the measure found.
evidence[]
The closest chunks, each with its base, path and heading_path, an excerpt, its containment (the fraction of the claim's words present in that chunk, rounded to six decimals), the words shared with the claim and the words still missing from the base.
notice
The caveat the terminal prints, verbatim, so a model reading this through another surface is told what a person is told: overlap is measured, judgement is not, and DELETE is never proposed.

When the base cannot be opened the error takes the same shape route uses, {"claim": ..., "error": ...} on stdout with exit code 1.

The MCP tools

What kb serve lists under tools/list. Four tools, none of which writes to the base, each returning one text part; the one file a refusal appends to is kb-misses.txt. Every tool answers through the same Memory contract the command line uses, so a model and a person cannot get different answers to one question.

The four tools

kb_route
{ "question": string, "top": integer }. question is required; top is optional and defaults to 5, or to the server's --top. Returns ranked file paths with the words that matched and the EVIDENCE line, and no file contents. On a miss it offers back the terms the base does know that look like the words used, and says that comparison is spelling rather than meaning.
kb_retrieve
The same two arguments. Returns the passages themselves, with the heading path and the provenance of each, under the EVIDENCE line. A passage from the deposit is marked [short memory: recent, not distilled, not yet in the library].
kb_remember
{ "claim": string }, required. Returns the proposal, the reason and the evidence, closest first, and ends with the same notice the command line prints. It writes nothing and decides nothing.
kb_fleet
{ }, no arguments. Returns the fleet's name and role and every agent with its role and directory, read from fleet.txt and each agent.txt. It is a lookup rather than a search, so it works on an empty library.

The EVIDENCE line

The line after the heading of every kb_route and kb_retrieve answer that found anything, in the words every other surface uses. Angle brackets stand for the numbers; the score and the floor are printed to one decimal and the margin to two. 

EVIDENCE: keyword score <s> against a floor of <f>; both|only one|neither of the two independent scorers ranked the top file; it leads the runner-up by <m>x. Verdict: ...

The verdict clause is one of three sentences: something here matches for a hit; a guess, too weak or too close to the runner-up to tell from a coincidence of vocabulary for a guess; nothing matched for nothing. Agreement is reported and never gates the verdict.

The handshake

The server is dual-era: it answers initialize when asked and never requires it, and it echoes back whatever protocol version the client named. When a legacy client names no version, the answer names 2025-06-18, the oldest widely deployed revision, because naming a newer one at a client that does not know it is how a handshake fails. The methods it answers are initialize, ping, tools/list and tools/call; a notification, a message with no id, gets no reply, not even an error. Stdout belongs to the protocol and every diagnostic goes to stderr.

Check codes

What kb check prints, from the linter's own source. A code beginning with E is an error and counts toward the exit code; a code beginning with W is a warning and counts only under --strict.

The codes

Note. There is no E03. It demanded a map file at the root, which was right while the index was built from map entries; since a note carries its own keys, a base with no map indexes perfectly well, and the rule was deleted rather than left to print one error per base forever.

What the checks skip

E02, W06 and W07 are asked of every file the index walks, not only of the knowledge folder, and they skip the files nobody searches for: README.md, MAP.md, CLAUDE.md, what-goes-here.md, MOVED.md, and anything under inbox/, records/ or a calculation-log/ folder. The deposit's invisibility to the catalogue is the feature, and a daily record keyed like a note would collapse the weight of every word it shares with the notes that answer questions.

Links inside fenced code blocks and inline code are ignored, because a base that documents its own link convention writes [[file-name]] in backticks and those are examples rather than references. The templates/ folder is exempt from link checks for the same reason: its links are placeholders. W04, W05 and E04 are asked only of a note in the knowledge folder that opens with front matter; a note with none gets no finding from them.

The linter does not judge whether a note is any good, and it has no notion of staleness yet: valid_for is required on a sourced note and nothing compares it to reality.

The files the tool reads and writes

Every file is plain text, and every file is where the folder is: nothing under a fleet carries an absolute path, so moving the folder moves everything.

Beside the fleet manifest

fleet.txt
The fleet's manifest, at the fleet root, as key = value lines with # for comments. name = and role = are what kb fleet prints for the fleet itself. classifier =, answerer =, promoter = and reviewer = each name a command that reads a prompt on stdin and answers on stdout, its path relative to the fleet root: the first chooses the agent at boot, the answerer writes prose for kb answer, the promoter proposes notes from the deposit and the reviewer decides on them. Each line is optional and none is guessed at: without the first, kb boot keeps the arithmetic's choice; without an answerer, kb answer prints the reading list; without a promoter or a reviewer, kb promote stops and names the missing line. attach = adds a base outside the fleet root; disable = names a child directory that is not a base.
kb-misses.txt
The recall loss log, beside fleet.txt rather than in .kb/, because the index is disposable and this is not. One line per distinct question the catalogue could not answer: count, first seen, last seen, then the question, with an indented looked like: line recording what the base offered back. Gitignored, because a question can be as private as an answer. KB_MISSES_PATH names a file, not a directory, and moves the log to a writable place; two fleets pointed at one path share one log.
kb-rejections.txt
What kb promote refused, counted, with the reason and the dates, beside kb-misses.txt and for the same reason. The same proposal refused three times is a gap in the base rather than a bad proposal. Gitignored, because a refusal quotes the note it refused.
.kb-promote.lock
The marker one promotion run holds so that another does not start over the same deposit. It exists for the minutes a run takes; --lock refuses to start while it is held. It survives a crash: a run within the hour refuses, and a later one takes the marker over and says which run died holding it.

Inside an agent

agent.txt
The card the catalogue reads to name and route. name = and role =; private =, one line of folders separated by commas, a trailing slash optional, . for the whole base, and the default of profile/, projects/ and records/ when the line is absent; ends =, where this agent stops, read by the command that chooses the agent, because a roster of roles says what each agent does and never what none of them does. A base with no agent.txt is read and can never be elected, which is what makes the person's base a base and not an agent.
blocks.txt
The constitution as labelled blocks, in stability order, most stable first, because prefix caching reuses a prompt only up to the first token that differs. A block is a [label] line followed by one file per line; a block is resident unless its label line ends in on-demand. The skeleton carries [identity], [user] pointing at ../person/core.md, [map], and [session] on-demand.
kb-aliases.txt
Optional, at the base root: alias = canonical, one per line, # for comments. Expansion is additive, so the original words always survive and a wrong line can add noise and never remove signal. A line is added after a real question missed, never before.
MAP.md
A reading list for a person, and a resident constitution block. Optional to kb check and to the index, and never read by the catalogue when it routes; required by kb write, which refuses when the agent has none.
inbox/
The deposit, the short memory. Files a person drops, and one inbox/<date>-session-<id>.md per captured session, with provenance: agent, stage: raw and no Search for line. Served and labelled short at every surface; read by kb promote.

The derived files

Everything under .kb/ is derived and disposable. Delete it and you have lost a rebuild, not a fact.

.kb/index.db
One SQLite file per base, and there is no flag to point it anywhere else. Two tables, readable with any sqlite3 binary. 
CREATE TABLE IF NOT EXISTS files (
    base        TEXT NOT NULL,
    path        TEXT NOT NULL,
    hash        TEXT NOT NULL,
    provenance  TEXT,
    stage       TEXT,
    private     INTEGER NOT NULL DEFAULT 0,
    PRIMARY KEY (base, path)
);

CREATE VIRTUAL TABLE IF NOT EXISTS chunks USING fts5(
    base         UNINDEXED,
    path         UNINDEXED,
    heading_path,
    text,
    tokenize = 'unicode61 remove_diacritics 2'
);

hash is a content hash, so an unchanged file is skipped on the next index. private is 1 for a file inside the base's declared private layer and 0 otherwise, two states and never a third. An index built before that column existed is emptied on open and index_was_rebuilt says so. The tokenizer folds accents, which is what lets a Portuguese question find an English note.

.kb/sessions/<id>
The agent last routed in a session, so kb boot emits the constitution only when it changes. Losing it costs one extra injection.
.kb/sessions/<id>.events
What kb boot appends on every message: a refused line with the question and the vocabulary offered back, or a routed line with the agent. kb capture reads it, writes the deposit, and deletes it only after the deposit is on disk, so a crash between the two captures again rather than losing the session.

The header of a note

Two labelled lines directly under the title, before the body. The first is the label the catalogue matches; the second is the one line the model that chooses the agent is shown in place of the file. The front matter above them is what W04, W05 and E04 read. 

---
provenance: agent
stage: derived
---

# The title

**Search for:** `first key`, `second key`, `a phrase a real question uses`

**Exists to:** say in one line what this file is for.

Both labels are read tolerantly: case does not matter, bold or plain, comma or semicolon, backticks optional, and the Portuguese Buscar por: and Existe para: are accepted. Only what sits above the first section heading is read, which is what keeps MAP.md, with one label per entry, from indexing itself as a file holding every key in the base. A line excludes itself from the text index; a heading would exclude everything after it, which is why the label is a line and not a section.
