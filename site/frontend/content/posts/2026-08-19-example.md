This file lives at `site/frontend/content/posts/`. It is markdown, it is in git, and
it is the source of truth for the page you are reading. Nothing else holds a copy.

Publishing is three steps and none of them involve a dashboard:

1. Write a `.md` file in that folder.
2. Give it a title and a date in the frontmatter at the top.
3. Commit and push.

The filename becomes the address. `2026-08-19-how-this-blog-works.md` is served at
`/blog/how-this-blog-works/`, because the date prefix keeps the folder in order for
whoever is reading it as files, and the reader does not need to see it.

## What the frontmatter takes

`title` and `date` are required and the build refuses to run without them, which is
better than publishing a post with no date and discovering it in a feed reader.
`description` is optional and is what shows on the index and in the feed. `slug`
overrides the address if the filename is not the URL you want. `author` defaults to
Richard.

## What you get for free

Ordinary markdown: headings, lists, `code`, [links](https://ulpia.io), quotes.

> A blockquote, set in the same type as the rest of the page.

The page inherits the site: the lamp still switches the scheme, the type is the same
Garamond, and an Atom feed at `/blog/feed.xml` updates itself when this file changes.
